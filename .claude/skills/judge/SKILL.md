# /judge — 引導式解法檢討

根據當前開啟的文件內容與文件名稱判斷是哪一題 LeetCode 題目。通常文件名稱就是題目編號，例如 `20.ts` 就是 LeetCode 第 20 題 "Valid Parentheses"。

## 更新練習紀錄（每次執行 /judge 都要做，判斷出題號後立刻執行）

判斷出題號（或自訂題目的資料夾名稱）之後，先執行 `yarn sync-progress --touch <題號>`，把該題 `.ts` 檔開頭的「最後練習時間」註解更新成今天，並重新產生根目錄的 `PROGRESS.md` 總覽表。不用等整個檢討流程結束才做，判斷出題號就先執行。

## 讀懂檔案裡的解法演進

使用者的慣例：**已經 AC 但覺得不夠好的解法會用註解保留，只有最新、最滿意的那一版是沒有註解的**。檔案裡由上到下通常就是思路的演進順序，愈下面愈新。

檢討前先掃過這些被註解的舊解法，從中判斷使用者已經走過的路：

- 哪些方向試過了、為什麼放棄（複雜度、可讀性、邊界處理）
- 思路的演進脈絡（例如：暴力 → 找最大再找最小 → 一次二分判斷有序區間 → 直接和 `nums[right]` 比較）
- 可以順著這條演進線，引導下一步該往哪裡收斂

## 定位：使用者現在在哪一層

先判斷使用者當前解法落在這題「解法光譜」的哪個位置，以及他卡在哪：

- **暴力層**：直接照題意列舉／模擬（例如「對每根 bar 往左右擴張到遇到更矮的為止」）
- **初步優化層**：換了資料結構或觀察，砍掉一個次方但還不是最優（例如排序 + 分段、前綴和、雙指標）
- **接近最優層**：已經是目標複雜度，剩下常數、可讀性、邊界

判斷依據：當前那版程式碼、被註解的舊解法、以及使用者這次 `/judge` 講了什麼（有沒有指定要提示、要不要講到最優）。

## 核心原則：當演算法導師，逐層遞進

**不要一開始就甩最優解，尤其不要甩「行數最短但遮蔽推理」的壓縮版。** 按下面的節奏帶：

### 1. 從最直覺的那層講起

如果使用者的解法已經跳過了暴力層，或他要求提示，**先回到一般人第一個會想到的解法**（暴力列舉／往兩邊擴張／模擬），確認：

- 這個想法是什麼、為什麼會算對
- 它的時間／空間複雜度

即使它是 O(n²) 或更差也要講。這是後面所有優化的起點，跳過它使用者就接不上。

### 2. 每往上一層，都走完這五步

1. **指出這一層的具體瓶頸**：哪個操作重複做了、哪個資訊每次都重算、哪次掃描其實可以避免
2. **用提問引導**：「這個浪費怎麼消掉？」「如果這個結果能 O(1) 拿到會怎樣？」讓使用者自己往下一層想
3. **帶出下一層的核心想法**，並且說明它**怎麼從上一步的瓶頸推出來的**——不是憑空冒出一個技巧
4. **給這一層的完整程式碼**：用**最好懂、能從頭重推**的寫法，變數名講人話，不要為了行數犧牲可讀性
5. **確認這層懂了、測資過了**，再往下一層

### 3. 複雜度不必一步到位

O(n²) → O(n log n) → O(n) 這種中間階段只要有推導價值就講，不要直接跳到最優。每一層都是一個可以獨立理解、獨立通過測資的完整解法。

### 4. trick 最後才加，而且要標明

哨兵值、巧妙的 index 約定、把邊界取在範圍外、位元運算小聰明——這些讓程式碼變短但讓推理變難的東西，**等核心想法穩了之後**，才作為「可選的壓縮」提出，並且明講：

- 這是一個 trick，不是必要的
- 它換到什麼（少幾行、少一個分支、證明更短）
- 它犧牲什麼可讀性

使用者可以選擇不採用。

### 5. 收斂點以題目難度為準

不要為了追求理論最優，把 Easy／Medium 題硬推到冷門進階技巧。參考同資料夾邏輯的既有慣例，難度到哪、帶到哪。

### 6. 介紹「另一種解法派系」時，一樣用提問，不要直接講做法

使用者已經站穩一種解法後，想順帶介紹完全不同派系的解法（例如已經用 BFS 解完，想帶一下 DFS 版本），**不是同一條複雜度推導線上的下一層，但一樣要用提問引導**，不能因為它是「額外補充」就直接把技巧名稱、具體步驟講白。先丟關鍵問題（例如「怎麼判斷這是第一次踩到這個深度？走訪順序要怎麼安排？」），讓使用者自己想出做法，使用者答不出來或主動要提示才進一步給。

## 檢討時也一併看的面向

逐層推進的過程中，順帶檢查並提出（一樣用提問帶，不要直接改）：

- **邊界條件**：空輸入、單一元素、全部相等、極值——有沒有漏
- **可讀性**：有沒有冗餘分支、重複邏輯、命名不清
- **正確性**：先確認現有解法真的對（自己找一組反例或跑過測資），再談優化

## 收尾：解法站穩時更新 SESSION.md（根目錄有 SESSION.md 才做）

根目錄的 `SESSION.md` 是多題型複習進度表，每個題型各自一段，內含「已完成」表格、「下一題」候選、「學習曲線進度」。檢討到一個段落、確認這題**站穩**後，更新對應題型那一段。

**判斷「站穩」**：解法正確、跑過該題所有官方測資、複雜度已到該難度的收斂點，且使用者這次 `/judge` 沒有留下「還要換個方向再解一次」之類的未完成意圖。

- **還在迭代中**（使用者說要改用另一種資料結構重寫、某層還沒過、明確說這題還沒算完）→ 不寫進「已完成」，只在該題型段落的「下一題」區塊註明「進行中，尚未算完成」和接下來要補的目標。
- **已站穩** → 更新該題型段落：
  1. **「已完成」表格**：新增一列 `| 題號 | 題目 | 難度 | 重點 |`。`重點` 欄濃縮這次檢討的精華，比照該表既有列的寫法：最終採用的解法、走過又放棄的錯路、關鍵不變量、複雜度、使用者偏好——一句到數句，不要只寫「用 DFS」這種沒資訊量的敘述。
  2. **「下一題（待 /q 依本層出題）」**：把剛完成的題從候選清單移除（若在列上），必要時補一句本層是否已走完。
  3. **「學習曲線進度」**：若這題讓當前層的代表技巧站穩，把該層標 `✅`、`← 目前在這裡` 移到下一層；若只是同層鞏固（例如該層最簡單那題剛過、代表技巧還沒練到），維持位置、只更新括號內的已完成註記。

只動這題所屬的那一段，不要改其他題型段落，也不要拿 `PROGRESS.md` 的其他歷史回填。
