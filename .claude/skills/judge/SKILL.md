# /judge — 引導式解法檢討

根據當前開啟的文件內容與文件名稱判斷是哪一題 LeetCode 題目。通常文件名稱就是題目編號，例如 `20.ts` 就是 LeetCode 第 20 題 "Valid Parentheses"。

## 更新練習紀錄（每次執行 /judge 都要做，判斷出題號後立刻執行）

判斷出題號（或自訂題目的資料夾名稱）之後，先執行 `yarn sync-progress --touch <題號>`，把該題 `.ts` 檔開頭的「最後練習時間」註解更新成今天，並重新產生根目錄的 `PROGRESS.md` 總覽表。不用等整個檢討流程結束才做，判斷出題號就先執行。

## 引導式檢討

根據使用者當前的解法，找出可以改進的地方，並用提問的方式循序漸進引導使用者思考改進的方向。以下是一些可以考慮的問題：

1. **時間複雜度**：目前的解法的時間複雜度是多少？是否有更優的演算法可以降低時間複雜度？
2. **空間複雜度**：目前的解法的空間複雜度是多少？是否有更優的演算法可以降低空間複雜度？
3. **程式碼可讀性**：目前的程式碼是否清晰易懂？是否有冗長或重複的部分可以簡化？
4. **邊界條件**：目前的解法是否考慮了所有可能的邊界條件？是否有漏掉的測試用例？

請根據以上幾點提供具體的改進建議，並說明為什麼這些改進會提升解法的效率或可讀性。

## 引導最佳解法的方式

若有標準最佳解法，不要直接貼出完整程式碼，而是從使用者目前的解法出發，一步步推導到最佳解法：

1. 先指出目前解法中某個可以優化的「操作」或「步驟」（例如：查表的時機、重複的判斷邏輯）
2. 用具體的提問引導使用者思考：「如果把這個步驟提前/移到別的地方做，會怎樣？」
3. 說明這個改動帶來的好處，並展示改動後的局部程式碼片段
4. 如果還有下一步優化，重複上述過程，逐步收斂到最佳解法
5. 最後再給出完整的最佳解法程式碼作為參考

重點是讓推導過程自然、不跳躍，讓使用者能理解「為什麼會想到這樣寫」，而不是憑空冒出一個技巧。
